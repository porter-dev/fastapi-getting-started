# FastAPI on Porter

A minimal FastAPI app, served by Uvicorn, ready to deploy on Porter.

## What's inside

- Python 3.14, FastAPI 0.157.0, Uvicorn 0.54.0
- A Dockerfile based on `python:3.14-slim` that runs as a non-root user

| Path | Method | Description |
| --- | --- | --- |
| `/` | GET | Confirms the app is running |
| `/healthz` | GET | Health check used by Porter |
| `/hello/{name}` | GET | Example route with a path parameter |
| `/docs` | GET | Interactive API docs generated by FastAPI |

## Run locally

```sh
python3.14 -m venv .venv
. .venv/bin/activate
pip install -r requirements-dev.txt
uvicorn main:app --reload --port 8000
pytest
```

With Docker:

```sh
docker build -t fastapi-getting-started . && docker run -p 8000:8000 fastapi-getting-started
```

Open http://localhost:8000 and http://localhost:8000/docs.

## Deploy on Porter

### From the dashboard

Fork this repo, then in https://dashboard.porter.run create a new app from your GitHub repo. Porter reads `porter.yaml`, builds the Dockerfile, and opens a PR adding a GitHub Actions workflow. Merge it and every push to `main` redeploys. See https://docs.porter.run/applications/deploy/deploy-from-github-repo.

### From the CLI

Install the CLI (https://docs.porter.run/cli/installation), then:

```sh
porter auth login
porter apply -f porter.yaml
```

## Configuration

`porter.yaml` defines one `web` service. It builds the Dockerfile at the repo root, runs Uvicorn on port 8000 with 0.25 CPU cores and 256 MB of memory, and uses `/healthz` as its health check. Full reference: https://docs.porter.run/applications/configuration-as-code/reference.

| Name | Required | Description |
| --- | --- | --- |
| `PORT` | No | Port Uvicorn listens on. Defaults to `8000`, which matches `port` in `porter.yaml`. |

Dependencies are declared in `requirements.in` and pinned in `requirements.txt`. To upgrade, run `uv pip compile requirements.in -o requirements.txt --upgrade`.
